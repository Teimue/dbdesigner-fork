Plugins

Plugins are separate programs which work on the current model. They are started from the Plugins Menu. DBDesigner Fork saves the model to a temporary file and starts the plugin with this file. While the plugin runs, the main window is disabled. When the plugin has changed the model, the changed model is loaded again and you are asked whether it should be saved.

The plugins use the stored database connections, the language and the font of DBDesigner Fork; a connection opened in DBDesigner Fork is offered to the plugin. The following plugins are installed with the program.

Data Browser

The Data Browser shows the rows of the tables in a connected database. Click [Connect ...] to choose a database connection. The list on the left shows the tables of the model, or all tables of the database when [All tables of the database] is checked.

  • Enter a condition in [Filter (WHERE)] to see only some rows; [Clear filter] removes it.
  • Click on a column title to sort the rows by this column.
  • [Max. rows] limits the number of rows that are read.
  • Double click on a value of a foreign key column to jump to the referenced row of the other table, following the relations of the model.

The Data Browser only reads; it does not change the database. The rows are copied into the grid, so no lock stays on the database while the window is open.

Test Data Generator

The Test Data Generator fills the tables of the model with plausible rows: names, addresses, dates, numbers and texts that fit the names and datatypes of the columns. Foreign keys refer to existing rows, the lengths of the columns are kept.

  • Select the tables and the number of rows per table ([Set for all] sets the same number for all tables).
  • Choose the target database, the language of the data, the share of NULL values and a seed. The same seed gives the same script.
  • Options: delete the existing rows first, leave auto increment columns to the database, COMMIT at the end.
  • [Generate] writes the script of INSERT statements. It can be copied, saved, or executed in a database with [Execute in database ...]; the execution runs in one transaction and is rolled back on an error.

Data Importer

The Data Importer imports text files into a table of a connected database: text with a separator (tabulator, semicolon, comma, space or another character, e.g. CSV files) or text in a fixed length format. On the Column Mapping page the fields of the file are assigned to the columns of the destination table; [Auto-Mapping] assigns fields with the same names. The settings can be stored as a preset and used again.

HTML Report

The HTML Report writes a description of the model as an HTML page: the tables with their columns, and optionally the regions, the indices and the table options. The tables can be sorted by position or by name.

Simple Web Front

The Simple Web Front creates PHP web pages for the tables of the model: lists of the rows, forms to enter and change them, with joins along the relations. The pages are grouped into views; the layout, the title and the output directory can be chosen. The database connection of the pages is entered on the first page of the plugin.

Demo

The Demo plugin shows how a plugin reads the model; it writes the SQL create statements of the selected tables. It is meant as a starting point for developers who want to write their own plugin.

Writing a Plugin

A plugin is a program named DBDplugin_<Name> (DBDplugin_<Name>.exe on Windows) in the directory of DBDesigner Fork. It is called with the file name of the model as its first parameter. The source code of the plugins in the directory Plugins of the project shows how the model classes of DBDesigner Fork are used.
